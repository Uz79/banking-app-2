# The assistant, second version (9f): requirements

Branch: `feature/assistant-nudges-and-handoff`

Roadmap item 9f (`specs/roadmap.md`). The opening's assistant (9b, `specs/2026-10-30-opening-assistant/`) waits to be asked: on desktop its column shows the invitation on every step, on a phone Help? sits in the bottom bar. This branch lets it notice when a customer seems stuck and offer one matching question, quietly, at most once per step, tuned by User Type; and it turns "Talk to an advisor" from one written line into a small simulated handoff: a callback or an appointment, a time, a confirmation. The intervention map (`designs/conversation/investment-opening/intervention-map.md`) is the input: its hesitation signals per step, its help levels and its rules (rule 4: no pop-ups, at most one proactive nudge per step, a dismissal is remembered; rule 5: a person is always the last option).

The interview settled: both parts in one branch with a simple handoff; the nudge appears in the assistant (the desktop column's invitation, a bubble above Help? on a phone), nothing new inside the step; a dismissal is remembered in the opening's session draft; the column stays the same for every User Type, only the nudges differ.

## Scope

**In:**

1. Hesitation signals on the opening's steps, measured in the browser only (D1 to D4)
2. Thresholds by User Type: Newbie, All-rounder, Power user (D5)
3. The nudge: one question per step, in the desktop column's invitation and as a bubble above the phone's Help? (D6 to D10)
4. Remembered nudges and dismissals in the opening's draft (D11)
5. The handoff: "Talk to an advisor" offers a callback or an appointment, three times, a confirmation; the exit screen's "Book an appointment" uses the same handoff (D12 to D16)
6. Documentation: the nudge and the handoff on the Components page's "Questions and answers" section (D19)

**Out (not in this branch):**

- Free text or keyword matching (9b's interview: chips only)
- Any change to the chips' answers, the panel's layout, the invitation for steps without a nudge, or the answer length by User Type (9b D9, D24 to D30)
- The column changing by User Type (interview: same column for everyone)
- Analytics or any signal leaving the browser (roadmap: signals stay in the browser; Vercel Analytics on Hobby has no custom events anyway)
- A real booking: no personal data entered, no calendar, no message sent (D14)
- The persona reacting (8b), personalisation (9g), the fridge (8a to 8e keep no assistant)
- Any change to the steps' content, answers, scoring or the summary

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **The signals** (the map's column "Hesitation signals"): **time** on a step against its expected reading time; **switching** between options (the third change of an answer on the same step); **going back** (Back pressed to reach this step, or a summary edit that returns here, the second time in the visit); **looking things up** (the second open of an in-step toggle: "What counts?" on tax, the information sheets on documents, "How is this worked out?" on risk); **left empty** (the amount field focused and left with nothing, or with a value under the minimum). Each step listens for the signals the map lists for it, plus time on every counted step | The map's list, made countable. "The third change" and "the second time" keep a single slip from counting |
| D2 | **Time is measured fairly:** the clock runs only while the step is on screen, the tab is visible and the assistant is not open on that step (desktop: past "Yes, help me"; phone: the full-screen layer). It starts over on every visit to a step. Typing or choosing does not reset it | A customer reading an answer, or away from the tab, is not hesitating |
| D3 | **Expected reading time per step** (placeholders in the config, `NUDGES` in `js/opening-assistant-config.js`): intro 15 s, knowledge 15, purpose 20, amount 20, risk 45, strategy 40, esg 15, tax 25, documents 40, summary 30. Completion and the exit screen have no nudge | One number per step, written down, to be tuned by watching tests, like the fridge's and the risk chart's |
| D4 | **A test switch:** `?nudge=fast` on the opening's URL (or the sheet's page) divides every expected time by 10, so a check does not wait 45 s. It is ignored otherwise and never stored | The checks must be runnable; the same pattern as `?reduced` |
| D5 | **Thresholds by User Type** (the map's help levels; interview: the column is the same, only the nudges differ): **Newbie** (`novice`) on every counted step, after 1.5x the reading time or at once on any other signal; **All-rounder** (`standard`, also when no profile is stored) only on the steps the map marks high (knowledge, amount, risk, tax, documents), after 2.5x the reading time or at once on another signal; **Power user** (`power`) never. The User Type is read once per step, as 9b's `level()` does | The map's table. Power user gets help only when asked |
| D6 | **One nudge per step, per opening:** each step has one nudge question in the config, one of its existing chips: intro "Can I stop and come back?", knowledge "What counts as basic knowledge?", purpose "What if I am not sure when I need it?", amount "What if I invest more than the fridge suggests?", risk "Is there a right answer?", strategy "Do I have to take the recommendation?", esg "Does it cost me return?", tax "Who counts as a US person?", documents "Which documents matter most?", summary "Can I still change something?". A step that has nudged does not nudge again in this opening, answered or not, and a step whose nudge question was already asked by the customer never nudges | Map rule 4: at most one proactive nudge per step. The question is one already written and reviewed (9b D7), so no new answer copy is needed |
| D7 | **Desktop: the invitation becomes the nudge.** The column's invitation (9b D25) changes in place: the title becomes the nudge question ("What counts as basic knowledge?"), the primary button reads "Show me", and a quiet text button "No, thanks" sits under it. The helper plays its wave once. "Show me" opens the conversation with that question already asked and its answer shown (as if the chip was tapped); "No, thanks" returns the invitation to "Questions about this step?" with "Yes, help me" and counts as dismissed. If the customer is already in the conversation on that step, nothing happens | Interview: in the assistant, nothing new inside the step. The column is already the place the eye goes for help |
| D8 | **Phone: a bubble above Help?** A small speech bubble rises above the Help? button in the bottom bar, with the nudge question and a close button (an X, accessible name "No, thanks"). Tapping the question opens the full-screen layer (9b D29) with that question asked and answered; the X dismisses it. It sits over the step's content, not in the layout, so nothing moves and the step still fits (the risk step's fit, 9e D11). Moving to another step or opening Help? removes it | Interview. The bubble points at the help that is already there; no height is added to tuned steps |
| D9 | **Gentle, never in the way:** no pop-up, no sound, no focus move. The bubble and the invitation change fade in over 0.2 s; with reduced motion they appear at once and the helper does not wave. One polite announcement for screen readers ("A question about this step: What counts as basic knowledge?") through the opening's existing status region, once per nudge | Map rule 4, mission principle 5. Focus stays where the customer is working |
| D10 | **Escalation to a person** (flagged, default): the third nudge shown in one opening, and any nudge on the documents or summary step, carries the advisor as well: on desktop a second quiet button "Talk to an advisor" under "Show me"; in the phone's bubble a second line "Or talk to an advisor". It opens the handoff (D12) | Roadmap: "escalating gently ... the last step is a handoff to a person". Several hesitations in a row are the sign a chip may not be enough |
| D11 | **Remembered in the draft** (interview): the draft (`uzBankWebOpeningDraft`, sessionStorage) gains `nudged: [screen ids]` (shown, whether used or dismissed) and `handoff` (D15). A resumed opening keeps them; completion and Start over clear them with the draft; closing the tab forgets them. An old draft without the keys reads as none. No new storage key | Interview. One session key since phone polish D1; `apps/web/README.md` describes the draft's shape and is updated |
| D12 | **The handoff starts from "Talk to an advisor"** (interview: a simple handoff), wherever it is (the chip, the quiet button, D10's escalation, the exit screen's button, D16). Its first answer: "We can call you back, or you can book a video meeting with an advisor." with two choices as chips: "Call me back" and "Book a video meeting" | Map rule 5. Two ways a person can help, as in the roadmap ("appointment or callback") |
| D13 | **Three times to choose from:** a callback offers three one-hour windows, an appointment three 30-minute meetings, all on working days between 8:00 and 18:00, starting from the next full hour plus one (never in the past, never on a weekend), worked out from the browser's clock. Shown as "Today, 15:00 to 16:00", "Tomorrow, 9:00 to 10:00", "Thursday, 14:00 to 14:30". Choosing one confirms it: "Done. An advisor will call you today, 15:00 to 16:00." or "Done. Your video meeting is on Thursday, 14:00 to 14:30. The link comes by email." Then "Your answers are kept." | Concrete and believable, still clearly a prototype; no free calendar to build |
| D14 | **Nothing is collected:** no name, phone number or email is asked or shown (the app has no customer contact data; the confirmation says "the number we have for you" if it needs one). No message or request is sent anywhere; the confirmation is the end of the simulation | The prototype must not look like it collects personal data (9b D10) |
| D15 | **A booked handoff is kept:** the draft's `handoff` holds `{ kind: 'call' or 'meeting', slot }` (the slot as an ISO time). Afterwards, "Talk to an advisor" answers with the booking ("An advisor will call you today, 15:00 to 16:00.") and offers "Choose another time" and "Cancel it". A booking whose time has passed is dropped when the draft is read | So the customer sees what they booked on every step, and can change their mind |
| D16 | **The exit screen uses the same handoff:** "Book an appointment" on the ineligible screen (9a D15) opens the assistant's handoff (desktop: the column's conversation; phone: the full-screen layer) instead of its own "We will call you to find a time." line. The screen then shows the booking from the draft ("An advisor will call you ..."), with Done | One handoff, one wording. The exit screen is where 9a first offered a person |
| D17 | **Copy:** "Show me", "No, thanks", "Or talk to an advisor", "Call me back", "Book a video meeting", "Choose another time", "Cancel it" are the customer's words; the assistant's lines say "we" and never "I" (9b D8). All of it in `js/opening-assistant-config.js` (`NUDGES`, `HANDOFF`). No em dashes, no exclamation marks | 9b D8, D30 |
| D18 | **Files:** new `js/opening-hesitation.js` (the signals, the clock, the thresholds; it calls back when a step should nudge); `js/opening-assistant.js` (the nudge in the invitation and the bubble, the handoff in the conversation); `js/opening-assistant-config.js` (`NUDGES`, `HANDOFF`); `js/investment-opening.js` (reports answer changes, Back, the toggles and the amount field; the draft's two keys; the exit screen's button); `css/styles.css` (the bubble, the handoff's time chips); `components.html` (D19); `apps/web/README.md` (the draft's shape). No new page, storage key or dependency | AGENTS.md conventions |
| D19 | **Documentation** (default, flagged): the Components page's "Questions and answers" section gets the nudge (the invitation with a question, the phone's bubble) and the handoff (the time chips and the confirmation), static | Mission principle 2: what is new becomes part of the system |
| D20 | **The merge gate** (default): `npm run build`; this branch's `validation.md` in a real browser (desktop and 390, Light and Dark, a Multi-color theme, keyboard, reduced motion, each User Type, `?nudge=fast`); the baseline smoke test; VoiceOver and touch by Klaudiusz on an iPhone on the preview, as in 9e | The standard gates plus the screen reader check, since the nudge is announced |
| D21 | **The phone's layer slides down when it closes** (review change): the mirror of its slide-up, with the flow sheets' timing (up 0.35 s ease-out, raised from 0.3 s; down 0.28 s ease-in). It applies to every close by the customer: the layer's X, "I can do it myself" and Escape. The handoff's end does not close the layer (the confirmation stays in it until the customer closes it), so it needs nothing. Focus returns to Help? once the slide has finished, and the sheet's header comes back then too. Closes the customer did not ask for (another step, leaving the opening, turning to the desktop layout) stay instant. Reduced motion: no slide, it closes at once. Desktop unchanged | The layer opened like a sheet but vanished at once, which read as a glitch; the flow sheets already set the timing |

## Context

- The assistant (`js/opening-assistant.js`): `setScreen(id)` resets help per step and shows the invitation on desktop (`inviting = wide`); `renderInvite()` builds the "Yes, help me" button; `ask(chip)` adds a question and its answer and is what D7 and D8 call with the nudge's chip; `level()` reads the User Type as D5 needs; `helper.wave()` exists. The phone's Help? button (`helpButton()`) is one element moved into each step's bottom bar by `render()` in `js/investment-opening.js` (about line 1069), so the bubble can hang off it.
- The draft (`js/investment-opening.js` lines 26 to 50): `{ page, fridge, step, answers, fridgeAmount, from }`, written by `saveDraft()` on every change and cleared on completion and Start over.
- The exit screen (`ineligible()`, about line 829) keeps a module-level `booked` flag and the line `INELIGIBLE.booked`; D16 replaces both with the draft's `handoff`.
- The toggles D1 counts: tax's "What counts?" (`investment-opening.js` about line 796), the documents' information sheets row (about line 846), the risk chart's "How is this worked out?" (`js/opening-risk-chart.js`).
- The app has no customer contact data (the only name is the payee "Hans Meyer" in `js/payment-state.js`), hence D14.

## Changed in the build

- D7: "Show me" moves focus to the conversation's title, not to a chip, so a screen reader starts at the answer's heading. "No, thanks" puts focus on "Yes, help me".
- D8: the bubble sits before Help? in the page, so Tab reaches it before Help? and Next.
- D15: once a handoff ends (booked or cancelled), "Talk to an advisor" is offered again on that step, so the booking can be changed there.
- D16: after booking from the exit screen, the screen updates quietly, without announcing the step again.
- D18: the time chips are the assistant's existing chips; no new CSS was needed for them.
